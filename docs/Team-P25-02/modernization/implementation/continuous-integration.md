## 1. Workflow

GitHub Actions runs on pushes to all branches and pull requests targeting `main`. Select Regression Tests maps changed paths to existing test files and records its decision in the job summary. Pushes to `main` and uncertain/shared changes run all regression test files. Documentation-only changes select none. Unit Tests, Integration Tests, and End-to-End Tests run only their selected files. The latter two still build isolated Compose environments and upload their result directories after test execution or failure. Regression Checks requires successful selection and requires each selected job to succeed; it accepts a skipped job only when selection chose no files for it. The duplicate full-unit coverage job was removed from this branch while coverage CI is being revised separately. Build, quality, and security jobs are not selected by this change. Staging deployment checks remain outside this workflow.

Unit suites use in-memory or mocked state and do not require live MongoDB or SMTP. Integration-test environment and execution details are in [the integration-test guide](testing/integration-test-environment.md) and [the API/database integration record](testing/api-database-integration.md).

## 4. Selective regression execution — local and hosted validation

The preceding [main run](https://github.com/jonpauljah/ProjectPeerEvaluation-P25-02/actions/runs/40790520102) took 493 seconds summed across its nine job durations, including 112 seconds for Integration Tests and 172 seconds for End-to-End Tests. Five recent successful runs ranged from 441 to 527 summed job-seconds. These are observed job durations, not GitHub billed minutes or post-change savings. A single E2E branch commit also produced separate [push](https://github.com/jonpauljah/ProjectPeerEvaluation-P25-02/actions/runs/40789951173) and [pull-request](https://github.com/jonpauljah/ProjectPeerEvaluation-P25-02/actions/runs/40789955678) runs.

This branch adds a pinned changed-path detector and [`scripts/selectRegressionTests.cjs`](../../../../scripts/selectRegressionTests.cjs). The selector's current inventory contains 9 frontend unit, 16 backend unit, 15 integration, and 6 browser test files. It selects exact changed test files, narrowly mapped frontend page tests, and report-controller tests across unit, access, API, and browser layers. Shared, unknown, deleted, invalid, or empty change sets select full suite discovery, including newly added test files. Main pushes also use full discovery. Documentation-only changes select none. Other backend controller changes select all tests because their connected impacts have not been mapped precisely enough to narrow safely. The selection job runs its own policy tests and records its reason plus exact files in selected mode. Regression Checks accepts a skipped job only when the selector chose no files for it and fails for selector failure or a selected job that did not succeed.

Local validation on the `fa78ac6` main base: 14 selector policy tests passed; the original ten-job YAML parsed; five shell simulations of the Regression Checks command matched expected success/failure; root lint and formatting passed. Full frontend unit tests passed 84/84 in 9 files, and full backend unit tests passed 143/143 in 16 files. Selected frontend Vitest ran 7 tests in one file; selected backend Vitest ran 2 tests in one file. The isolated integration runner ran `tests/integration/roster.test.js` only (12 passing tests; run `11efec53808d87ec`, exit 0, cleanup verified). The isolated E2E runner ran `tests/e2e/smoke.spec.cjs` only (2 passing tests; run `583312ecc35c187b`, exit 0, cleanup verified). Their `result.json` files and logs are under ignored `test-results/` in the worktree.

Hosted probes against the earlier ten-job version: [documentation-only #142](https://github.com/jonpauljah/ProjectPeerEvaluation-P25-02/actions/runs/40967566518) skipped all three regression jobs but still ran Unit Test Coverage; [frontend #143](https://github.com/jonpauljah/ProjectPeerEvaluation-P25-02/actions/runs/40967573428) passed selected unit and E2E with integration skipped; [backend #144](https://github.com/jonpauljah/ProjectPeerEvaluation-P25-02/actions/runs/40967574991) passed selected unit, integration, and E2E; [full fallback #145](https://github.com/jonpauljah/ProjectPeerEvaluation-P25-02/actions/runs/40967582177) passed all regression suites; [deliberate failure #146](https://github.com/jonpauljah/ProjectPeerEvaluation-P25-02/actions/runs/40967862747) failed Unit Tests and Regression Checks as expected. This branch now removes the redundant coverage job. No measured CI savings or required-check enforcement is claimed; the final nine-job workflow still needs a hosted run.

The source-to-test map needs review whenever dependencies or tests change. Exact-file selection cannot prove that an unselected test would pass on a PR commit; full main-branch runs provide the broader check after merge. The separate coverage job is absent from this branch pending its independent revision. Even one selected service-backed file incurs Compose startup, and separate push and PR triggers can still duplicate work. These limits remain material when evaluating actual cost after a hosted trial.
