## 1. Event workflows

The workflow handles pull requests and merge-group candidates targeting `main`, without workflow-level path filtering. It records the event base/head and merge-base change set. Documentation-only changes in either event explicitly select no application tests; the unit, API integration, browser E2E, CI policy-test, and coverage jobs skip while build, lint/format, both security scans, selection, and `CI Gate` still run. Code PR changes run both complete unit suites once with coverage and select API integration/browser E2E tests conservatively. API integration coverage contributes to changed-line coverage; browser E2E does not. The PR Changed-Line Coverage job combines unit reports with any selected API runtime report and evaluates the 80% changed-executable-line minimum. Missing or invalid coverage evidence fails.

For merge-group code candidates, selection forces full unit, API integration, and browser E2E discovery, including changes from earlier candidates in the queue. The Overall Line Coverage job combines canonical unit coverage with the full API runtime capture and enforces at least 70% line coverage independently for frontend and backend. Browser E2E does not contribute coverage. The final `CI Gate` job evaluates all job outcomes for either event. The workflow has no `push` trigger; push-to-main CI is deferred to Milestone 3. Repository ruleset and merge-queue enforcement are external settings and are not asserted by workflow source alone.

Full fallback rebuilds its inventory from current test files, including newly added and renamed tests, so missing historical paths do not stop selector evidence collection. Added application/test files choose full discovery; added documentation remains a valid no-test selection. The explicit frontend journey mapping now includes reset/relaunch for `StudentEvaluation.jsx` and results export for `CourseManagement.jsx`. These mappings are maintained starting points, not a completeness claim.

The coverage manifest includes production frontend/backend JavaScript and JSX, including zero-hit unvisited files. Frontend unit coverage uses canonical original-source Istanbul instrumentation. Backend unit coverage is collected from V8 and normalized to Istanbul for the canonical report; API runtime coverage uses V8. Inputs carry per-source hashes and combine by original source identity. Separate package reports preserve all four metrics; changed executable lines require 80% on PRs, and merge-group code candidates require 70% overall line coverage per package. The historical sponsor goal for critical-workflow code remains separate in the [quality-gate policy](../../requirements/quality-gate-policy.md). Instrumented hits do not establish complete functional workflow coverage.

Selection, unit, selected integration, E2E, and coverage artifacts use SHA/run/attempt-specific names. The selection artifact is uploaded for every candidate. Unit and service-test artifacts exist only when those suites run; docs-only candidates therefore have no unit, service-test, or coverage artifact, but retain the selection and OWASP Dependency-Check report. For PR code candidates, the Changed-Line Coverage job validates selected input provenance, combines unit reports with selected API coverage, and uploads a changed-line report with normalized inputs, merge plan, provenance/manifest, HTML, LCOV, JSON, four-metric summaries, and missed lines. Successful merge-group code candidates upload a separate Overall Line Coverage artifact with the full suite report. See the [developer guide](../../developer-guides/continuous-integration.md) for local commands. Unit suites require no live database; service-backed runners use isolated Compose stacks and capture API coverage before verified cleanup.

`CI Gate` evaluates every job and rejects unexpected skipped or failed work. Historical repository settings observations are not current verification of required-check or merge-queue enforcement; inspect live settings before making that claim.
