## 1. Event workflows

The workflow handles pull requests and merge-group candidates targeting `main`, without workflow-level path filtering or test-selection skips. For PR patch measurement, `scripts/regressionChanges.cjs` supplies changed-path and merge-base evidence. Every candidate, including documentation-only changes, runs both complete unit suites with coverage and the complete API integration suite. Full browser E2E runs for merge-group candidates and is event-inapplicable for pull requests. API integration coverage contributes to changed-line coverage; browser E2E does not. The PR Changed-Line Coverage job combines unit reports with the full API runtime report and evaluates the 80% changed-executable-line minimum. Missing or invalid coverage evidence fails.

For every merge-group candidate, the workflow runs full unit, API integration, and browser E2E suites. The Overall Line Coverage job combines canonical unit coverage with the full API runtime capture and enforces at least 70% line coverage independently for frontend and backend after the unit and API integration suites succeed; it may run alongside browser E2E. Browser E2E does not contribute coverage. The final `CI Gate` job evaluates all job outcomes for either event, accepting only event-inapplicable skips. The workflow has no `push` trigger; push-to-main CI and post-merge verification are deferred to Milestone 3. Repository ruleset and merge-queue enforcement are external settings and are not asserted by workflow source alone.

The changed-path and merge-base evidence supports PR patch measurement; it does not select or skip test suites. Test commands discover complete current suites, including newly added and renamed tests. Documentation paths receive the same required unit and API integration execution as other paths.

The coverage manifest includes production frontend/backend JavaScript and JSX, including zero-hit unvisited files. Frontend unit coverage uses canonical original-source Istanbul instrumentation. Backend unit coverage is collected from V8 and normalized to Istanbul for the canonical report; API runtime coverage uses V8. Inputs carry per-source hashes and combine by original source identity. Separate package reports preserve all four metrics; changed executable lines require 80% on PRs, and merge-group code candidates require 70% overall line coverage per package. The historical sponsor goal for critical-workflow code remains separate in the [quality-gate policy](../../requirements/quality-gate-policy.md). Instrumented hits do not establish complete functional workflow coverage.

Unit, integration, E2E, and coverage artifacts use SHA/run/attempt-specific names. Unit and integration artifacts are produced for every candidate; merge-group candidates also produce E2E and overall-line artifacts, while PR candidates produce the changed-line artifact. Documentation-only candidates retain the same required suite and coverage evidence as other changes. The PR Changed-Line Coverage job validates unit and full API input provenance, combines reports, and uploads a changed-line report with normalized inputs, merge plan, provenance/manifest, HTML, LCOV, JSON, four-metric summaries, and missed lines. Merge-group candidates upload a separate Overall Line Coverage artifact with the full suite report. See the [developer guide](../../developer-guides/continuous-integration.md) for local commands. Unit suites require no live database; service-backed runners use isolated Compose stacks and capture API coverage before verified cleanup.

`CI Gate` evaluates every job and rejects unexpected skipped or failed work. Historical repository settings observations are not current verification of required-check or merge-queue enforcement; inspect live settings before making that claim.
