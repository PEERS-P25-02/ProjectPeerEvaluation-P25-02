## 1. Session-A workflow

The workflow checks the immutable head of pull requests targeting `main` and temporarily `ci/selective-regression` for probe PRs, without workflow-level path filtering. It records the event base/head and merge-base change set. Documentation-only changes explicitly skip application tests while build, quality, security, and `CI Gate` still run. Code changes run both complete unit suites once with coverage. API integration and browser E2E tests use conservative selection; only the API integration coverage is included in the patch report. A valid initial report below 80% triggers complete API integration discovery only when selection is `selected` and the report contains missed backend lines. A below-minimum report with only frontend misses, or one already based on full API discovery, is below threshold and fails without further broadening. When broadening runs, the initial unit reports are reused and combined with the broad API runtime capture for final enforcement; browser E2E remains selected and does not contribute coverage. Missing or invalid coverage evidence fails.

The coverage manifest includes production frontend/backend JavaScript and JSX, including zero-hit unvisited files. Frontend unit coverage uses canonical original-source Istanbul instrumentation. Backend unit coverage is collected from V8 and normalized to Istanbul for the canonical report; API runtime coverage uses V8. Inputs carry per-source hashes and combine by original source identity. Separate package reports preserve all four metrics; changed executable lines require 80%. Overall floors remain inactive. The historical sponsor goal for critical-workflow code remains separate in the [quality-gate policy](../../requirements/quality-gate-policy.md). Instrumented hits do not establish complete functional workflow coverage.

Selection, unit reports, service-backed results/raw captures, and initial/final combined reports are retained in SHA/run/attempt-specific artifacts. Each producer exposes its immutable upload artifact ID, suite, SHA, run ID, and attempt; consumers download exact IDs and validate embedded provenance. The coverage plan and decision record each input producer separately from the coverage consumer's attempt. Different attempts within one SHA and workflow run are valid for partial reruns. Combined output includes normalized inputs, merge plan, provenance/manifest, HTML, LCOV, JSON, four-metric summaries, and patch decision. When API broadening is required, the final report reuses the initial unit evidence and incorporates the full API capture. See the [developer guide](../../developer-guides/continuous-integration.md) for local commands. Unit suites require no live database; service-backed runners use isolated Compose stacks and capture API coverage before verified cleanup.

`CI Gate` evaluates every required job and rejects unexpected skipped or failed work. Repository settings remain a separate enforcement requirement: the last live inspection found main unprotected and its ruleset disabled with legacy check names. Session A does not activate those settings or add merge-group/push triggers.
