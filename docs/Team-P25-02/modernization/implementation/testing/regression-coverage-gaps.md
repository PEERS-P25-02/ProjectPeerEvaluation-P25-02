# Critical Workflow Regression Coverage Gaps

**Status:** Temporary internal gap record. It tracks implementation coverage against the [functional regression matrix](../../../requirements/regression-test-matrix.md); it is not a sponsor approval record or current execution report.

## Scope and interpretation

The target is CW-01 through CW-09, including evaluation reset and relaunch in CW-05. Standalone reminders (OP-33-24) and account-support operations (OP-33-34–36) are outside this targeted gap audit; their existing tests remain required to pass. MFA, automatic team assignment, AI, deadline enforcement, token refresh, and multiple retained evaluation campaigns are not added to the target.

This source audit inspects assertions against all 74 matrix targets, including authentication/authorization, email integration, and browser E2E suites. **Present**, **partial**, and **missing** describe source assertions against each matrix outcome; they do not by themselves establish successful execution. The target and expected outcomes remain unchanged. The audit currently classifies 61 targets as Present, 8 as Partial, and 5 as Missing; these are source-assertion classifications, not a code-coverage percentage. The [authentication and authorization integration record](authentication-authorization-integration.md) summarizes the relevant tests. The [email integration record](email-integration.md) documents a full October 26, 2026 integration run that passed 176 tests in 12 files, plus a separate concurrent run. Browser test cases and historical local execution evidence are recorded in [End-to-End Browser Testing](end-to-end-testing.md). These are execution results, distinct from the source audit; the October 28 submission integrity verification passed 12 focused tests and 188 tests across the full integration suite, as recorded in [Section 5 of the API/database record](api-database-integration.md#5-submission-integrity). The October 28 reset-sequencing follow-up is recorded separately in the [frontend validation record](frontend-unit-test-validation.md#october-28-follow-up-required-reset-before-team-changes). The older API/database run documented in [Section 4 of its integration record](api-database-integration.md#4-expanded-verification-and-review) remains historical.

Frontend page tests use mocked API boundaries; they establish UI behavior and request handling, not server persistence or cross-layer browser journeys. The integration suite sends HTTP requests to the application and checks MongoDB and isolated Mailpit state. The browser suite now covers a smoke check, repeatable fixtures, and four selected workflows; see the [E2E record](end-to-end-testing.md). Selected browser journeys provide evidence for REG-CW01-01, REG-CW02-01, REG-CW03-01, REG-CW04-01, REG-CW05-03 through REG-CW05-05, REG-CW06-01, REG-CW08-01, and REG-CW09-01/02/07. The suite does not establish every matrix outcome. The policy's [scope and pass rules](../../../requirements/quality-gate-policy.md#1-scope-and-passfail-rules) and [test traceability requirements](../../../requirements/quality-gate-policy.md#4-test-planning-and-traceability) remain authoritative; this inventory does not change matrix expectations.

Historical passing execution evidence is recorded in the implementation documents; the October 28 frontend reset-sequencing execution is recorded in the [frontend validation record](frontend-unit-test-validation.md#october-28-follow-up-required-reset-before-team-changes).

For each target, keep the matrix outcome unchanged, add or identify executable assertions that match it, and retain successful run evidence with its exact source/version and result. Historical October 24 results remain historical and must not be relabeled as current. A documented plan, source-file presence, or adjacent behavior alone does not resolve a gap; resolution requires a matching executable assertion **and** successful execution evidence.

This record remains temporary until every matrix target has matching passing evidence. Keep sponsor-facing matrix outcomes unchanged and maintain links to durable tests, RTM mappings, and dated results as coverage grows. Existing test suites outside this target remain required to pass.
